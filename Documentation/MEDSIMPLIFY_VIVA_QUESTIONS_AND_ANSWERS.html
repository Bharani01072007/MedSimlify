📌 Section 1: Project Overview & Clinical Motivation

Q1. What is MedSimplify, and what real-world problem does it address?
Problem Statement

MedSimplify is an AI-powered medical report simplification and digital healthcare assistant platform designed to transform complex, jargon-heavy diagnostic lab reports into clear, plain-language summaries.

The Core Problem: Diagnostic reports (such as Complete Blood Counts, Dengue profiles, and Liver Function Tests) are saturated with clinical terminology, abbreviations, and numerical reference ranges. Over 80% of patients cannot interpret their own test results without clinical guidance. This knowledge gap causes severe patient anxiety, delayed medical intervention, and dangerous self-medication.

Our Solution: MedSimplify enables patients to upload reports in PDF, DOCX, or photo formats. It extracts text via multi-modal OCR, identifies biomarkers using Clinical NER, and generates a dual-layer explanation: a Standard Medical Summary and an ELI5 (Explain Like I'm 5) analogy-based summary in English and regional Indian languages (Hindi, Tamil, Telugu), alongside a 24/7 RAG AI health assistant.

Q2. Who are the primary target users and stakeholders of your platform?
Stakeholder Analysis

Our system is designed for two distinct user roles with dedicated interfaces:

  • 1. Patients and Caregivers: Access plain-language report explanations, actionable recovery checklists, medication reminders, daily symptom tracking, and localized regional translations.
  • 2. Doctors and Healthcare Clinicians: Access the Doctor Clinical Portal to review incoming patient reports, receive automated 'Red Flag' alerts for critical cases (such as a rapid 50% platelet decline in Dengue), review auto-generated clinical EMR SOAP notes, and manage daily consultation queues.
Q3. How does MedSimplify differentiate itself from existing apps like Practo, Apollo 24/7, or ChatGPT?
Competitive Advantage
  • Versus Telemedicine Portals (Practo, Apollo): Existing apps operate merely as digital storage repositories; they deliver raw PDF files without interpreting what the biomarker numbers mean for the patient. MedSimplify actively decodes the data into intuitive analogies and flags dangerous trends.
  • Versus Generic LLMs (ChatGPT): Public chatbots are prone to medical hallucinations and have no direct access to structured hospital databases. MedSimplify uses a deterministic Clinical NER pipeline to cross-verify test ranges against clinical baselines and uses RAG (Retrieval-Augmented Generation) to ground answers directly in the patient's verified records.
Q4. What are the primary diagnostic report categories supported by MedSimplify?
Domain Scope

MedSimplify is trained and optimized for five major clinical diagnostic categories:

  1. Hematology Panels: Complete Blood Count (CBC), Platelet counts, Hemoglobin, WBC differential, RBC indices.
  2. Serology & Viral Profiles: Dengue NS1 Antigen, Dengue IgM/IgG antibody profiles.
  3. Metabolic & Diabetes Panels: Fasting Blood Sugar (FBS), Postprandial Glucose, HbA1c average blood sugar.
  4. Biochemistry Panels: Liver Function Tests (LFT - Bilirubin, SGOT, SGPT) and Lipid Profiles (Cholesterol, Triglycerides, HDL, LDL).
  5. Clinical Prescriptions & Discharge Summaries: Medication dosages, frequencies, and hospital admission course notes.

⚙️ Section 2: System Architecture & Technology Stack

Q5. Explain the high-level technical architecture of your project.
System Design

MedSimplify follows a decoupled, 4-tier service-oriented architecture:

  • 1. Presentation Tier (Frontend): Built with React 19, TypeScript, and TanStack Router within a mobile-viewport container, styled using TailwindCSS and Radix UI primitives.
  • 2. Application / API Tier (Backend): Powered by Python 3.10+ and FastAPI with asynchronous endpoints, CORS middleware, JWT authentication, and Pydantic validation.
  • 3. Clinical Intelligence Tier (AI/NLP): Integrates PyMuPDF, OpenCV, and PyTesseract for OCR; clinical transformer models for NER; a dual-layer simplification engine; Helsinki-NLP translation; and a RAG retrieval system.
  • 4. Data Tier (Persistence): Hosted Supabase PostgreSQL database managed via SQLAlchemy 2.0 ORM, featuring a local SQLite fallback and dynamic primary key sequence synchronization.
Q6. Why did you select FastAPI over Flask or Django?
Backend Justification

We evaluated Python web frameworks and chose FastAPI based on three technical benchmarks:

  1. Asynchronous Concurrency: FastAPI natively supports Python's async/await paradigm on top of Starlette and Uvicorn (ASGI). This allows non-blocking execution during heavy I/O operations (file uploads and ML model inferences).
  2. Native Pydantic Data Validation: Eliminates manual validation code. Incoming JSON and form fields are automatically validated against Pydantic schemas with compile-time type hints.
  3. Execution Performance & Swagger UI: FastAPI operates at speeds comparable to NodeJS and Go, and automatically generates interactive OpenAPI documentation at /docs for rapid API testing.
Q7. Why use React 19, Vite, and TanStack Router instead of older React setups?
Frontend Engineering
  • React 19 & TypeScript: Provides compile-time type safety, preventing undefined property errors during clinical data parsing, and supports modern state hooks.
  • Vite Bundler: Replaces outdated Webpack bundlers by leveraging native ES Modules (ESM) in development, providing millisecond Hot Module Replacement (HMR) and optimized Rollup production builds.
  • TanStack Router: Delivers 100% type-safe file-based client-side routing, route context providers, built-in search parameter validation, and scroll restoration for a native-mobile app feel.
Q8. How does your client communicate with the backend?
API Integration

Communication is handled through a centralized asynchronous API client (frontend/src/lib/api-client.ts):

  • Dynamically resolves the API host URL (http://localhost:8000/api).
  • Automatically attaches the stored JWT token in the HTTP Authorization: Bearer <token> header for authenticated endpoints.
  • Handles multipart/form-data for image and PDF file uploads.
  • Provides unified error handling that intercepts network failures and delivers user-friendly feedback.

🧠 Section 3: Artificial Intelligence, OCR & Clinical NLP

Q9. How does the multi-modal OCR pipeline extract text from different document types?
OCR Pipeline

Our OCR service handles multiple file extensions using specialized extraction pathways:

  • 1. PDF Documents: Processed via PyMuPDF (fitz). It accesses the native vector text layer directly from electronic PDFs, achieving near 100% character accuracy without pixel distortion.
  • 2. Word Documents (.docx): Extracted structurally by parsing paragraph and table elements using python-docx.
  • 3. Scanned Paper Photos (.png, .jpg): Processed via an OpenCV computer vision pre-processing pipeline before text extraction through PyTesseract using page segmentation mode 6 (--oem 3 --psm 6).
Q10. What image pre-processing techniques are used before passing an image to Tesseract?
Computer Vision

Mobile camera photos of lab reports often suffer from low contrast, shadows, and camera noise. Our OpenCV pipeline applies four sequential transformations:

  1. Grayscale Conversion: Removes extraneous color channels, reducing processing complexity.
  2. Contrast Alpha Scaling: Enhances text legibility using cv2.convertScaleAbs(gray, alpha=1.5, beta=30).
  3. Median Blur Filtering: Removes salt-and-pepper grain noise without blurring character edges.
  4. Otsu's Adaptive Thresholding: Automatically computes the optimal threshold separating foreground text pixels from paper background pixels, creating a clean black-and-white binary image.
Q11. What is Clinical Named Entity Recognition (NER), and what entities does it extract?
Clinical NLP

Clinical NER is a specialized natural language processing task that identifies medical terms in unstructured text and maps them to structured clinical entities.

In MedSimplify, our NER service extracts:

  • Biomarker / Test Name: e.g., Platelet Count, Hemoglobin, WBC, HbA1c, SGOT.
  • Numerical Value: e.g., 45,000, 11.2, 140.
  • Unit of Measurement: e.g., cells/mcL, g/dL, mg/dL, %.
  • Clinical Status: Automatically classified into Normal, Low, High, or Critical based on standardized clinical reference ranges.
Q12. How does your dual-layer simplification engine work (Standard vs ELI5)?
Explainable AI

To cater to different educational levels, MedSimplify generates two distinct explanations for every finding:

  • 1. Standard Medical Explanation: Formulated for educated patients or consulting doctors using proper clinical terms. (e.g., "Platelets are essential blood cell fragments necessary for hemostatic plug formation and clotting.")
  • 2. ELI5 (Explain Like I'm 5) Mode: Uses real-world visual analogies. (e.g., "🩹 Think of platelets as tiny construction workers carrying band-aids inside your blood pipes. When you get a cut, they rush over and patch the hole! Right now, your body's repair crew is low on workers, so you bruise easily.")
Q13. How does MedSimplify prevent AI hallucinations on sensitive medical lab data?
Safety & Reliability

We enforce a strict Zero-Hallucination Architecture:

  1. Deterministic Extraction: Test numbers, units, and ranges are extracted using validated clinical regex patterns and token classifications—never open-ended generative text.
  2. Clinical Knowledge Base: Reference ranges are verified against WHO, ICMR, and CDC laboratory baselines.
  3. Retrieval-Augmented Grounding (RAG): Health assistant responses are strictly anchored to the patient's retrieved lab test values, explicitly preventing the model from hallucinating non-existent conditions.
Q14. What is RAG (Retrieval-Augmented Generation), and how does the AI Assistant use it?
RAG Architecture

Retrieval-Augmented Generation (RAG) combines document retrieval with generative AI to produce grounded, accurate answers:

  1. Retrieval: When a patient submits a question, the backend queries the database for the patient's active lab reports using their report IDs.
  2. Augmentation: The extracted biomarker values (e.g., Platelets: 45,000 cells/mcL, Dengue NS1: Positive) are injected into the model's system context.
  3. Generation: The assistant produces an answer explicitly referencing the patient's real data (e.g., warning against taking NSAID pain relievers like Aspirin or Ibuprofen which worsen bleeding in thrombocytopenia), citing the exact report ID as evidence.
Q15. How does the multi-lingual regional translation service work?
Localization

MedSimplify supports regional Indian languages: Hindi (hi), Tamil (ta), and Telugu (te).

It utilizes pre-trained sequence-to-sequence translation models (Helsinki-NLP/opus-mt-en-hi/ta/te) coupled with a validated medical term translation dictionary. This guarantees clinical terms are accurately translated (e.g., Platelet Count → "இரத்த தட்டணுக்கள் எண்ணிக்கை" in Tamil, "प्लेटलेट काउंट" in Hindi) rather than incorrectly transliterated.

💾 Section 4: Database Engineering & Backend Operations

Q16. Why did you implement a dual PostgreSQL and SQLite database strategy?
DevOps & Resilience

In production environments, MedSimplify uses a cloud-hosted Supabase PostgreSQL database for connection pooling, ACID transaction guarantees, and multi-user concurrency.

However, during local development or viva demonstrations with restricted internet access, cloud database connections can fail. Our configuration in backend/config/database.py tests the PostgreSQL connection on startup; if it encounters a network timeout, it seamlessly and automatically falls back to an embedded local SQLite database (medsimplify.db) with zero crashes or code modifications.

Q17. What is the PostgreSQL sequence desynchronization problem, and how did you resolve it?
Database Internals

The Problem: PostgreSQL manages auto-incrementing primary keys via independent sequence counters (e.g., users_id_seq). When initial mock records with explicit IDs (like id=1, 2, 3) are manually seeded into tables, the internal sequence pointer is not updated. When a new user registers, PostgreSQL attempts to assign id=1, triggering an IntegrityError / UniqueViolation 500.

The Solution: We created an automated resynchronization utility (sync_db_sequences) that runs on server startup, executing:

SELECT setval(pg_get_serial_sequence('tbl', 'id'), COALESCE((SELECT MAX(id) FROM tbl), 1));

This re-aligns the serial counter to the maximum primary key across all 13 database tables.

Q18. How are user security and role-based access control implemented?
Cybersecurity
  1. Password Hashing: Raw passwords are never stored in the database. They are cryptographically hashed using Bcrypt with auto-generated salt rounds.
  2. Stateless JWT Tokens: On successful authentication, the server generates a JSON Web Token (JWT) signed with HS256 containing the user ID, role (patient or doctor), and expiration timestamp.
  3. Role-Based Access: Frontend routes and backend endpoints check the user type, ensuring patients can only view their own medical records while doctors have access to clinical analytics and queue management.
Q19. How is the medication adherence score calculated?
Algorithm Design

Medication adherence is mathematically calculated as:

Adherence (%) = ( Total Taken Doses / Total Scheduled Doses ) × 100

This score directly drives the visual progress bar on the patient home screen (e.g., 3 out of 4 doses logged = 75% adherence), providing patients with positive behavioral reinforcement.

🧪 Section 5: Edge Cases, Testing, Limitations & Future Scope

Q20. What happens if a patient uploads a blurry or completely unreadable image?
Error Handling

Our OpenCV pipeline evaluates image contrast and character confidence during Tesseract execution. If the text length is under 15 characters or character confidence falls below the accepted threshold, the system flags the file.

Rather than returning garbled predictions or crashing, the application displays a friendly warning banner: "Image is too blurry or low contrast. Please retake the photo in bright lighting or upload a direct PDF."

Q21. How did you test and validate your application?
Testing & QA

We executed testing across four core tiers:

  • 1. OCR & Parsing Accuracy: Tested with authentic diagnostic lab reports (CBC, Dengue profiles, LFT) in PDF and camera image formats to evaluate character extraction fidelity.
  • 2. API Integration Testing: Verified all REST routes (/reports, /auth, /chat, /medicines, /symptoms) using FastAPI's Swagger UI and automated Python unit tests.
  • 3. Edge Case Testing: Evaluated system resilience against missing form fields, duplicate emails, and sudden database connection drops.
  • 4. User Acceptance Testing: Evaluated readability and comprehension improvements when toggling between standard medical and ELI5 analogy explanations.
Q22. What are the current limitations of MedSimplify?
Critical Appraisal
  1. Cursive Handwritten Prescriptions: While printed reports achieve over 95% accuracy, cursive handwriting on doctor prescription slips remains challenging for general OCR models.
  2. DICOM Radiographic Scans: The system parses textual radiology impression summaries, but does not yet perform direct computer vision segmentation on raw X-ray or MRI DICOM scan images.
  3. Compute Hardware: Running full 7B parameter LLMs locally requires dedicated GPU resources; lightweight client setups rely on medical dictionary lookups and cloud endpoints.
Q23. What is the future scope of this project?
Future Enhancements
  • IoT Wearable Integration: Connecting smartwatch APIs (Apple Health, Google Fit) to correlate real-time heart rate and SpO2 with lab biomarkers.
  • Vision Transformers (ViT) for Radiography: Training multi-modal vision models to segment and highlight abnormalities directly on chest X-rays.
  • Voice-Assisted Audio Support: Adding Speech-to-Text and Text-to-Speech in Tamil and Hindi for illiterate or visually impaired patients.
  • HL7 / FHIR Standards: Adopting international health data interchange standards for seamless interoperability with hospital EMR systems.
